1. Alcance de --no-fetch

  • Sesión de ingeniería: ruta /api/v1/market-series?read_only=1 → backend pasa --no-fetch al CLI → cero upstream; ausencia en caché devuelve motivo NO_COVERAGE sin intento de fetch.
  • Explorador normal: /api/v1/market-series sin read_only → sin --no-fetch → adquisición bajo demanda sujeta a presupuestos existentes (ledger compartido, pages ≤ 2, 30 req/min).

2. Recuperación por identidad autoritativa

  • Al recargar con sesión abierta, el contexto se carga con symbol/intervalo del config de la sesión recuperada, nunca con las propiedades predeterminadas del componente.
  • Se muestra referencia de entrada y configuración recuperada: session_id, símbolo, intervalo, config_hash, regla, reloj T, revisión, entry_px fijo.

3. Sincronización de reloj

  • Actualización centralizada tras cada respuesta autoritativa (applyAuthoritative). Si cambia clock_ms (incluido Entrar), indicadores y contexto BTC se recalculan para ese T.
  • Mientras se actualiza, el contexto anterior se descarta (marketSeries = null); no se muestran valores previos como actuales.
  • Transiciones probadas: entrada, paso, salida, reinicio y recuperación.
